# Sweep — Design

Date: 2026-11-07
Status: draft for review

Source: the owner's written brief (the "Build Sweep" spec pasted 2026-11-07) plus the UI direction chosen in conversation. Items marked **[builder call]** were decided by Claude, not the owner, and can be changed.

## 1. Intent

A native macOS app for developers that finds where disk space went, explains it in plain terms, and reclaims it safely. All scanning, measuring, classifying and deleting is deterministic, unit-tested code. An LLM is used only to turn a finished, redacted scan report into readable insights and ranked recommendations. It never decides what is deleted, never sees file contents, and never runs commands.

The app should feel playful and optimistic: Mac OS 8 "Platinum" structure with iMac G3-era candy controls ("Gumdrop Platinum"). The fun is in the parts you touch; the data stays easy to read.

### Goals
- Accurate accounting: physical bytes, correct handling of dataless cloud files, APFS clones, firmlinks and mount points. No false alarms.
- Safe reclamation with a dry-run plan, per-tier confirmation, and honest per-path results.
- Regrowth tracking with root-cause hints, so the user fixes causes, not only symptoms.
- Optional scheduled maintenance.
- Optional LLM insights that are a bonus and never a dependency.

### Non-goals
- General consumer "Mac cleaner" features (RAM cleaning, malware scanning, app uninstaller for the sake of it).
- Mac App Store distribution (sandbox makes the core job impossible).
- Cloud sync, accounts, telemetry.

### Anti-goals (failure even if it "works")
- Deleting anything the user didn't see in a plan and confirm.
- Reporting space as reclaimable that won't actually be freed (clones, dataless files, SIP paths).
- Sending file contents, raw usernames, or sensitive-data file names to any LLM.
- Treating Apple "Operation not permitted" on protected caches as failures, or hiding real failures.
- A UI that's fun but hard to read, or alarmist copy.

## 2. Constraints

- macOS 14+ deployment target, Apple Silicon only. Dev machine: macOS 26.6, Xcode 26.6, Swift 6.3.
- SwiftUI app; Swift 6 language mode with strict concurrency.
- Not sandboxed; distributed as a Developer ID–signed, notarized app **[builder call — follows from needing FDA, `Process`, and arbitrary paths]**.
- No shell for executors: every external tool runs as a direct `Process` with argv, full stderr capture, no pipes that can SIGPIPE the child. Avoid zsh entirely. Resolve tool binaries to absolute paths first (`uv`, `docker`, `brew`, `xcrun`, `git`, `npm`, `pnpm`, `go`, `cargo`); if missing, the detector reports "tool not installed" and skips.
- Known gotchas to code around: no GNU `timeout` (implement timeouts in Swift), zsh `nomatch` and builtin shadowing (`log` → `/usr/bin/log`) are avoided by not using a shell, BSD `find -newermt "-14 days"` fails silently (do mtime logic in Swift).
- Test runs on this machine: cap parallel workers at 3 (`swift test --parallel --num-workers 3`), never run full suites from several sessions at once.
- Minimal third-party dependencies **[builder call]**: none in `SweepCore` beyond Apple SDKs and system `libsqlite3`. If YAML is wanted later, add it then; rules ship as JSON.

## 3. Architecture

```
Sweep/
  Package.swift                 SwiftPM: SweepCore (library), sweep (CLI executable), tests
  Sources/SweepCore/            scanners, accounting, rule engine, executors, history, redaction, insights client
  Sources/sweep/                CLI: `sweep scan --json`, later `sweep plan`, `sweep run`
  Tests/SweepCoreTests/         unit tests + fixtures
  Rules/rules.json              detector rules (bundled; user override in App Support)
  App/                          Xcode project (generated by XcodeGen from project.yml) [builder call]
    SweepApp/                   SwiftUI dashboard + MenuBarExtra
    SweepAgent/                 LaunchAgent helper executable
  docs/
```

- **SweepCore**: no UI. Fully unit-tested. Exposes async APIs that stream progress events (for the live log and the CLI).
- **sweep CLI**: thin wrapper over SweepCore; milestone 1's deliverable and a test harness for everything after.
- **SweepApp**: SwiftUI dashboard window + `MenuBarExtra`.
- **SweepAgent**: small executable launched by a per-user LaunchAgent plist (`~/Library/LaunchAgents/…sweep.agent.plist`) to run opt-in maintenance; logs to `~/Library/Logs/Sweep/`.
- **Insights**: module in SweepCore that builds the redacted summary, calls the provider, validates output. Off by default.
- **History**: SQLite at `~/Library/Application Support/Sweep/history.db`, via a thin wrapper over system `sqlite3` **[builder call]**.
- Bundle ID: proposed `dev.algamthe.sweep` (see §16; pending owner confirmation and Team ID).

## 4. Scan model

```
Item {
  id               stable across scans (hash of category + canonical path or tool key)
  category         rule id, e.g. "cache.uv", "artifact.node_modules", "vm.parallels"
  path             absolute path, or tool-scoped pseudo-path (e.g. "docker://builder/default")
  logicalBytes
  physicalBytes    allocated bytes; 0 for dataless; discounted for known clones
  lastModified
  lastUsedSignal   best evidence of last use (atime is unreliable; prefer tool logs, git, app logs)
  risk             tier 1–4
  action           enum: toolCommand(argv) | trash | hardDelete | revealInFinder | gitWorktreeRemove | pkgForget | none
  rebuildCost      low | medium | high (+ human text, e.g. "re-downloads ~4 GB")
  evidence[]       short strings explaining classification ("no commits in 41 days", "dev server not running")
}
```

### Risk tiers
1. **Safe / regenerable** — caches that rebuild themselves. Confirmed as one batch.
2. **Idle build artifacts** — regenerable but tied to projects; must pass the idle check. Confirmed per item.
3. **Needs decision** — VMs, personal data, toolchains, apps, sim runtimes. Confirmed per item.
4. **Protected / dead end** — shown with the reason, never actionable.

## 5. Accounting (dashboard headline)

- Free space: `volumeAvailableCapacityForImportantUsage` (and `statfs` for raw).
- APFS container breakdown from `diskutil apfs list -plist`: System, Preboot, VM, Data, simulator volumes, other.
- Bucket walk of: `~`, `/Applications`, `/Library`, `/opt`, `/usr/local`, `/private/var`, `/System/Volumes/Data/System`. **Unaccounted** = used − sum of buckets, explained as mostly TCC-protected folders (Mail, Messages, Safari, etc.) with a Full Disk Access prompt deep-linking to System Settings (`x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`).
- Physical size via `totalFileAllocatedSize`. Skip dataless files (`SF_DATALESS` in `st_flags`); iCloud/OneDrive/Dropbox placeholders count 0 local bytes.
- APFS clones: deleting a clone frees roughly nothing. Known clone-heavy paths (e.g. Chrome `code_sign_clone` under `/var/folders`) are flagged "du overstates, won't free space" and move to Tier 4. **[builder call]** Detect clone-sharing generally where cheap (e.g. `ATTR_CMNEXT_PRIVATESIZE` / private size via `getattrlistbulk`) and fall back to the known-path list otherwise.
- No crossing mount points or firmlinks (`du -x` semantics): compare `st_dev`, skip firmlink targets, count each inode once (track `(dev, ino)` for hard links).
- CoreSimulator: don't trust `du` (mounted DMGs). Use `xcrun simctl runtime list -v` for runtime sizes.
- Local snapshots: list via `tmutil listlocalsnapshots /`; explain purgeable lag after big deletes.

## 6. Detectors

Rules live in `Rules/rules.json` (bundled) with an optional user override at `~/Library/Application Support/Sweep/rules.json`, merged by rule id. A rule declares: id, tier, path globs or tool probe, size method, preconditions (process checks, idle checks, tool present), action, rebuild cost, explanation text. Detectors that need logic beyond data (git worktrees, lsregister parsing, VSCode extension grouping, Docker builders) are Swift "detector kinds" that rules parameterize. The rules file must cover every detector below.

### Tier 1 — safe caches (prefer the tool's own command over rm)
- **uv**: size via `uv cache size` when available. `uv cache prune` is always allowed. `uv cache clean` only when no `uv`/`uvx` processes run.
- **npm**: `npm cache clean --force`. `~/.npm/_npx` only if no `npm exec`/`npx` process runs.
- **pnpm** `pnpm store prune`; **bun** `~/.bun/install/cache`; **pip** cache; **Homebrew** `brew cleanup -s`; **Gradle** caches; **Go** `go clean -cache`; **Cargo** registry cache.
- **`~/Library/Caches/*`**: "Operation not permitted" on Apple-protected caches is expected; counted separately, not reported as failures. Call out Sparkle/ShipIt staged updates (VSCode, Codex, Postman).
- **`~/.cache/*`**: puppeteer, codex-runtimes, playwright, huggingface, torch, whisper. Model caches: rebuildCost high.
- **Chrome `OptGuideOnDeviceModel`** (~4 GB, re-downloads).
- **Xcode** DerivedData, old Xcode Previews.
- **Docker**: `docker builder prune -f`; prune each buildx builder by NAME from `docker buildx ls` (not the `buildx_buildkit_*` container name); dangling images. Then shrink `Docker.raw` with `docker run --rm --privileged --pid=host alpine nsenter -t 1 -m -- fstrim -av` (ignore "discard not supported"). Never touch running containers or volumes. Unused tagged images → Tier 3. Docker steps run only if the daemon is already up; Sweep never starts Docker/Colima itself **[builder call]**.
- **VSCode/Cursor duplicate extensions**: group `~/.vscode/extensions/<publisher.name>-<version>*` (and Cursor's equivalent); keep newest by mtime. Requires the editor to be quit (`pgrep`).

### Tier 2 — idle build artifacts
Artifacts: `node_modules`, `.next`, `.open-next`, `.sst`, Rust `target/`, `.venv`/`venv`, `.turbo`, `dist`, `__pycache__`, `.transformers_cache`.

Project discovery **[builder call]**: walk user-configured project roots (default: `~/Documents`, `~/Developer`, `~/Projects`, `~/code`, `~/src`, `~/Desktop` if they exist), find project markers (`.git`, `package.json`, `Cargo.toml`, `pyproject.toml`), don't descend into artifacts.

A project is idle only if **all** hold:
- no source file (excluding artifact dirs) with mtime newer than N days (default 14), computed in Swift;
- last git commit older than N days (if a git repo);
- no dev server running whose cwd/args point at it (`pgrep -f "next dev|sst dev|vite|turbo"` then match cwd via `proc_pidinfo`).

**Git worktrees**: list with `git worktree list --porcelain`. Offer removal only if clean (`status --porcelain` empty), has an upstream, and is 0 commits ahead. Use `git worktree remove` (keeps the branch). Show "merged to main: yes/no" as info.

Per project show: artifact size, last commit date, idle days, rebuild command.

### Tier 3 — needs decision
Parallels/UTM/VMware VMs (last-run date from logs/config), simulator runtimes (`xcrun simctl runtime delete <id>`), TeX Live, anaconda/miniconda (warn if it provides the first `python3` on PATH), local LLM models (ollama, LM Studio; detect duplicate blobs by size+hash), files > 1 GB in Downloads/Documents, old installers (.dmg/.pkg/.zip), unused Docker images, DerivedData for uninstalled Xcode versions.

**Sensitive-data detector**: large CSV/XLSX/Parquet/JSON files inside project folders flagged as possible PII. Shown with a suggestion to move to approved storage. Never uploaded; names never sent to the LLM (not even hashed in a reversible way). Size threshold default 50 MB **[builder call]**.

### Leftovers of uninstalled apps
- Read the Trash via Finder AppleScript (`NSAppleScript`, needs Automation permission for Finder). Get bundle IDs from `lsregister -dump` by parsing each record's `path:` and `identifier:` together; records are delimited by dashed lines.
- Search by bundle ID and app name in: Application Support, Caches, Preferences, Containers, Group Containers (team-ID prefix), Application Scripts, Saved Application State, Logs, HTTPStorages, WebKit, LaunchAgents, `/Library/{LaunchAgents,LaunchDaemons,PrivilegedHelperTools,Application Support}`, pkg receipts (`pkgutil --pkgs`), dotdirs (`~/.config`, `~/.local/share`, `~/.cache`).
- Don't remove shared vendor items if a sibling app from that vendor is still installed. Don't remove a CLI sharing a name with a deleted app if its binary/data was modified recently; ask instead.
- Sandboxed `~/Library/Containers/*`: report as "remove via Finder" with a Reveal in Finder button.
- Receipts and other admin-owned items: v1 shows Reveal in Finder / a copyable `sudo pkgutil --forget` command (see §16).

### Tier 4 — dead ends (display only)
SIP-restricted files (`restricted` flag), e.g. CoreSimulator `Caches/dyld`, stale MobileAsset sim runtimes that re-mount; dataless cloud files; APFS clones.

## 7. Regrowth and root causes

- Every scan stored (per-item physical bytes + timestamp). Show per-item growth rate (GB/day over a configurable window, default 14 days) and "time to full disk" at current trend.
- Deterministic root-cause hints:
  - processes writing to caches: `pgrep -fl "uvx|uv run|npm exec"`;
  - MCP configs: parse `~/.claude/plugins/**/.mcp.json`, `~/.claude.json`, Cursor/VSCode MCP configs for `uvx …@latest` / `npx …@latest` servers (they re-resolve every agent session);
  - duplicate MCP servers across plugins (same package, different versions);
  - orphaned MCP processes from dead sessions (parent PID 1).
- Maintenance schedules (opt-in each, logged to `~/Library/Logs/Sweep/`): weekly `uv cache prune`, `npm cache verify`, `brew cleanup`, Docker builder prune.

## 8. Safety rules (hard requirements)

- Dry run first, always. The plan screen shows every path, size, risk, rebuild cost and the exact command. Tier 1 confirmed as a batch; Tier 2/3 per item.
- Non-cache items go to the Trash (`FileManager.trashItem`); hard-delete caches and Tier 2 build artifacts only (see §15).
- Executors: direct `Process`, full stderr, per-path results ("12 removed, 3 protected by macOS").
- Re-measure after execution; show expected vs actual freed; explain APFS lag; re-check after 60 s.
- Never touch: running containers/volumes, Dropbox/iCloud/OneDrive folders, Keychains, Mail/Messages data, anything in a git worktree with changes, or any path on the user's protected list. Enforced in a single `SafetyGuard` that every executor calls immediately before acting (re-checks preconditions at execution time, not only at plan time) **[builder call]**.
- Full Disk Access requested gracefully; everything else works without it, with "unaccounted" clearly labelled.

## 9. Decisions memory

Per item: "keep" or "never ask", with an expiry (default 90 days for keep, none for never ask **[builder call]**). Stored in history.db. Also feeds the LLM summary ("user declined Parallels 3×").

## 10. LLM insights (only LLM use)

- Off by default. Works fully without it.
- Input: redacted JSON summary built by code — bucket totals, top-N items with sizes, tiers, regrowth rates, last-used dates, root-cause hints, prior decisions. Usernames → `~`. Project and file names under Documents/Desktop/Downloads genericized (`project_07/node_modules`) unless the user opts in. No file contents. No sensitive-data file names.
- Output contract (JSON schema, validated): `{ headline, insights[{title, detail, evidenceItemIds[]}], recommendations[{itemIds[], action, expectedBytes, risk, why}], maintenanceSuggestions[], questionsForUser[] }`. Reject any reference to item IDs not in the input. The app computes and displays all byte totals itself; LLM numbers are never shown.
- Provider: Anthropic Messages API, default model `claude-sonnet-5-5`, API key in Keychain. Local option: any OpenAI-compatible or Ollama endpoint on localhost **[builder call]**.
- "View payload" shows exactly what will be sent before the first call. Failure leaves the app fully usable; insights are a bonus panel.

## 11. UI — "Gumdrop Platinum"

Reference mockup: https://claude.ai/artifact/Ta1xoU1m3BKpd9cDzmvHUu (option 2). Earlier exploration: https://claude.ai/artifact/4jq4MZ4fyQy2eW2R8WRKSf.

### Visual language
- **Platinum chassis**: light grey (#dcdcdc) windows and panels, 1 px bevels (white top-left, #8a8a8a bottom-right), inset white wells for lists, grooved title-bar stripes tinted with the current flavour, square-ish corners (7 px window top corners, 7 px panels).
- **Candy controls**: glossy pill "gumdrop" buttons in the flavour colour, round jelly progress/usage bars with a gloss highlight and moving barber-pole stripes while working, round gumdrop close box, fruit-coloured category segments.
- **Flavours**: Blueberry (#2f7fd6, default), Bondi (#0a9bb8), Strawberry (#e2445c), Tangerine (#ff8a1f), Grape (#8a4fc7), Lime (#5fbf2f). One accent token drives buttons, stripes, selection, chart lines, mascot body and the menu-bar icon. Picked in Settings.
- **APFS segment colours** (fixed, independent of flavour): System graphite, Preboot grape, VM tangerine, Data blueberry, Simulators lime, Free near-white.
- **Type** **[builder call]**: Barlow Semi Condensed (UI, bold for labels/numbers) and Varela Round (buttons, balloons, mascot speech). Both OFL, bundled. Tabular numerals wherever digits align.
- **Dark mode** **[builder call]**: a "Graphite" Platinum — dark grey chassis (#2b2d31 family) with the same bevel logic inverted, flavours slightly brightened. Follows system appearance.
- **Mascot**: original pixel trash can (12×13 grid) with a face. Moods: happy (>20% free), nervous (<10%), sweating (<5%), asleep (nothing to sweep), hop on successful sweep. Name TBD.
- Legal: open fonts and original icons only; no Apple logo, Apple system fonts, or classic Apple icons.

### Screens
- **Dashboard**: menu-style header; mascot + free-space gauge with speech balloon; APFS container bar + legend; bucket treemap (click to drill down) with an "Unaccounted" tile and FDA prompt; "Reclaimable now" (Tier 1 total + Sweep button); "Needs your decision" list; growth chart (top regrowing items).
- **Plan → Confirm → Execute → Verify**: plan table grouped by tier (path, size, risk, rebuild cost, exact command); Tier 1 batch checkbox, per-item toggles for Tier 2/3; execute view with live log (window-shade collapsible) and per-item results; verify view with expected vs actual and the APFS-lag note with a 60 s re-check.
- **Item detail**: evidence list, last used, growth sparkline, Keep / Never ask (with expiry), Reveal in Finder.
- **Insights panel**: headline, insights, recommendations linking to items, View payload button.
- **Settings**: flavour, project roots, idle days, protected paths, maintenance schedules, insights provider/key, sounds.
- **Menu-bar extra**: free GB, 7-day sparkline, "Run safe sweep", low-space and growth-spike alerts (`UNUserNotificationCenter`).

### Delights (in scope)
Flavour picker; Balloon Help toggle (yellow balloons explaining why each item is safe and what rebuilds it); mascot moods; jelly bar physics (slight overshoot on shrink); window-shade log; optimistic, plain copy ("Room to breathe again."). Optional sound pack (original sounds, off by default) is deferred to after milestone 6 **[builder call]**. All motion respects Reduce Motion.

### Accessibility
Every control has a VoiceOver label; colour is never the only signal (tier badges carry text); contrast meets WCAG AA in both appearances; full keyboard navigation in plan/confirm.

## 13. Testing

Unit tests in SweepCore for: rule matching, idle detection, size accounting (including dataless and clone cases with fixtures), redaction, LLM output validation. Fixtures are built in a temp dir at test time (sparse files, hard links, `chflags` where possible); cases that need real dataless files or clones use recorded `stat` fixtures behind a `FileSystemProbe` protocol **[builder call]**. External tools are behind a `CommandRunner` protocol with recorded outputs for tests.

## 15. Resolved after builder review

- **Cloud-synced Desktop/Documents** **[builder call]**: SafetyGuard blocks any path inside an iCloud Drive, Dropbox or OneDrive root. Sweep reads Finder's `FXICloudDriveDesktop` / `FXICloudDriveDocuments` settings; when either is on, that folder counts as an iCloud root, and artifacts found there are shown in Tier 4 as "synced folder, not touched". On the owner's Mac both are off (checked 2026-11-07), so `~/Documents` projects are eligible.
- **Trash vs hard delete** **[builder call]**: caches *and* Tier 2 build artifacts (node_modules, target/, .venv, etc.) are regenerable, so they are hard-deleted. Tier 3 items (VMs, downloads, installers, models, leftovers) go to the Trash. Worktrees use `git worktree remove`. Verification reports "freed now" and "moved to Trash (frees when emptied)" separately. The verify screen offers an "Empty Trash" button, and only Sweep's own items are counted as trashed bytes.
- **Redaction scope** **[builder call]**: project and file names are genericized under Documents, Desktop, Downloads **and every configured project root**, unless the user opts in.
- **Leftovers scope** **[builder call]**: v1 finds leftovers only for apps currently in the Trash, as in the brief. Scanning for orphans of long-gone apps is deferred.
- **Plan scope** **[builder call]**: a detailed implementation plan for milestone 1, with an outline of milestones 2–6. Each later milestone gets its own detailed plan after review.

## 16. Owner decisions after builder review (2026-11-07)

- **Unattended runs — "Routine sweep" subset, fully disclosed** (owner: "be clear and let the user know what we are doing; I don't want us to get blamed for their inability to read").
  - The menu-bar "Run safe sweep" and scheduled maintenance only run the *routine* subset: low-rebuild-cost Tier 1 tool commands and caches (`uv cache prune`, npm cache, `brew cleanup -s`, pnpm store prune, `go clean -cache`, Xcode DerivedData, `docker builder prune`). Rules mark membership with `routine: true`.
  - Never in routine runs: high-rebuild-cost items (huggingface/torch/whisper model caches, Chrome `OptGuideOnDeviceModel`), Docker `fstrim`, `uv cache clean`, VSCode extension dedupe, anything Tier 2–4. These are also unticked by default in the full plan.
  - Disclosure, so the user can't miss it:
    1. Routine runs are off until the user enables them on a one-time sheet that lists every command and folder in plain words with typical sizes and rebuild cost. The sheet needs an explicit "I understand what this removes" checkbox before the Enable button activates. Default focus is on Cancel.
    2. The menu-bar popover shows, directly above the button, a short list of what will run and the estimated size ("Removes: uv cache old versions, npm cache, Homebrew downloads… ~9.2 GB").
    3. Every run (manual or scheduled) ends with a notification summarising what was removed and freed, links to a full per-path log in `~/Library/Logs/Sweep/`, and appears in the app's history.
    4. If the routine list changes (rules update), routine runs pause until the user re-confirms the new list.
- **Admin-owned leftovers** (`/Library/LaunchDaemons`, `PrivilegedHelperTools`, `/Library/Application Support`, package receipts): v1 has no privileged helper. They are listed with "Reveal in Finder" (Finder asks for the password). Receipts show a copyable `sudo pkgutil --forget <id>` command. A privileged SMAppService helper is a later milestone. This replaces the brief's "pkgutil --forget via an authorization prompt" for v1.
- **Signing**: halalgami has an Apple Developer account. Developer ID signing is set up from milestone 2 (the first app build) so Full Disk Access and Automation permissions survive rebuilds. The `sweep` CLI is a developer and test tool in v1, not shipped to end users. **Pending from owner:** Team ID and final bundle ID (proposed `dev.algamthe.sweep`, with `dev.algamthe.sweep.agent` for the LaunchAgent).
